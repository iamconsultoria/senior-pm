Diagnose a project problem using the `senior-project-manager` skill in DIAGNOSE mode.

Symptom: $ARGUMENTS

Work from symptom to root cause to intervention. Use the symptom-to-intervention mapping in
`references/11-tailoring.md` — it covers poor deliverable quality, teams unsure how to proceed,
siloed teams, approval delays, excess work in progress, disengaged stakeholders, lack of
transparency, and recurring surprise risks.

Every intervention in that table changes the system rather than adding a control. Hold that
line: resist prescribing more process, more reporting or another review gate. Adding governance
to a struggling project produces a slow struggling project.

Finish with the check that will prove the intervention worked, and by when.
